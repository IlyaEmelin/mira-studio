# Mira Studio FAQ Bot

## Краткое описание

`service_studio_bot` — локальный Telegram FAQ-бот для небольшой студии услуг Mira Studio. Бот помогает клиентам быстро получить ответы на типовые вопросы и передаёт индивидуальные обращения владельцу или оператору.

Первая версия является MVP: бот работает локально через long polling, использует настоящий Telegram-бот, хранит обращения в SQLite и не содержит секреты в исходном коде.

## Проблема и цель

### Проблема

Клиенты Mira Studio часто задают в Telegram одинаковые вопросы:

- какие услуги доступны;
- сколько стоит услуга;
- как записаться;
- как подготовиться;
- где находится студия или как связаться со специалистом.

Оператору приходится вручную отвечать на повторяющиеся вопросы, а индивидуальные обращения могут теряться в переписке.

### Цель

Собрать простого Telegram-бота, который:

- отвечает на частые вопросы через FAQ-меню;
- распознаёт часть текстовых вопросов по ключевым словам;
- корректно обрабатывает неизвестные вопросы;
- принимает одно короткое обращение после явного выбора связи с оператором;
- сохраняет обращение в SQLite;
- уведомляет владельца через `OWNER_CHAT_ID`.

## Пользователи и роли

### Клиент студии

Пользователь Telegram, который хочет получить быстрый ответ или оставить индивидуальное обращение.

### Владелец или оператор

Получатель уведомлений о новых обращениях. Telegram chat id владельца хранится в переменной окружения `OWNER_CHAT_ID`.

## Основные сценарии

### Сценарий 1. Старт бота

1. Пользователь отправляет `/start`.
2. Бот отправляет приветствие от Mira Studio.
3. Бот показывает inline-меню FAQ.

Ожидаемый результат: пользователь понимает, что бот принадлежит Mira Studio, и видит доступные разделы FAQ.

### Сценарий 2. Ответ через FAQ-кнопку

1. Пользователь нажимает одну из FAQ-кнопок.
2. Бот показывает заранее подготовленный ответ.
3. Меню остаётся доступным для дальнейших вопросов.

Ожидаемый результат: каждая FAQ-кнопка возвращает свой ответ, повторные нажатия не ломают сценарий.

### Сценарий 3. Текстовый вопрос по ключевым словам

1. Пользователь отправляет обычное текстовое сообщение.
2. Бот ищет ключевые слова в тексте.
3. Если найдено совпадение, бот отправляет соответствующий FAQ-ответ.

Примеры сообщений для проверки:

- `Какая стоимость?`
- `Как записаться?`
- `Где вы находитесь?`
- `Как подготовиться?`

Ожидаемый результат: бот отвечает подходящим FAQ-ответом без записи обращения в SQLite.

### Сценарий 4. Fallback для неизвестного вопроса

1. Пользователь отправляет текст без известных ключевых слов.
2. Бот не падает и не сохраняет сообщение как обращение.
3. Бот предлагает выбрать FAQ-кнопку или связаться с оператором.

Ожидаемый результат: неизвестный текст обрабатывается безопасно и понятно для пользователя.

### Сценарий 5. Обращение к оператору

1. Пользователь нажимает «Связаться с оператором».
2. Бот сообщает, что ждёт следующее сообщение как обращение.
3. Пользователь отправляет короткий текст.
4. Бот сохраняет обращение в SQLite.
5. Бот подтверждает пользователю приём обращения.
6. Бот отправляет уведомление владельцу, если `OWNER_CHAT_ID` задан корректно.
7. Состояние ожидания обращения завершается.

Ожидаемый результат: после сохранения обычные сообщения пользователя снова обрабатываются как FAQ или fallback.

## Объём первой версии (MVP)

### Входит в MVP

- Telegram-бот на `aiogram==3.28.2`.
- Локальный запуск через long polling.
- Загрузка настроек из `.env` через `python-dotenv==1.2.2`.
- Переменные окружения:
  - `BOT_TOKEN`;
  - `OWNER_CHAT_ID`;
  - `DB_PATH`.
- Команда `/start`.
- Inline FAQ-меню с кнопками:
  - «Услуги»;
  - «Стоимость»;
  - «Как записаться»;
  - «Подготовка»;
  - «Связаться с оператором».
- Callback-ответы на FAQ-кнопки.
- Распознавание текстовых вопросов по ключевым словам.
- Fallback для неизвестных вопросов.
- Одношаговый режим обращения к оператору.
- Сохранение обращения в SQLite.
- Уведомление владельца через `OWNER_CHAT_ID`.
- Логирование запуска и ошибок без вывода секретов.

### Не входит в MVP

- Автоматическая запись на услугу.
- Онлайн-оплата.
- Интеграция с CRM.
- Интеграция с календарём.
- Веб-админка.
- Авторизация операторов.
- Многошаговая анкета клиента.
- История обращений внутри Telegram для оператора.
- Деплой на сервер.
- Внешние API.

## Функциональные требования

### `/start`

- Бот должен обрабатывать команду `/start`.
- В ответ бот должен отправлять короткое приветствие и FAQ-меню.
- Приветствие должно явно указывать на Mira Studio.

### FAQ-меню

- Бот должен показывать inline-кнопки.
- Каждая FAQ-кнопка должна иметь отдельный callback identifier.
- Нажатие FAQ-кнопки должно возвращать заранее подготовленный текст.
- Повторное нажатие кнопок не должно приводить к ошибке.

### FAQ-ответы

Минимальный набор ответов:

#### «Услуги»

Mira Studio помогает с индивидуальными услугами для клиентов: консультации, подготовка, сопровождение и подбор решения под задачу. Напишите оператору, если хотите уточнить услугу под вашу ситуацию.

#### «Стоимость»

Стоимость зависит от услуги и объёма работы. Базовая консультация — от 1500 ₽. Точную цену специалист подскажет после короткого описания задачи.

#### «Как записаться»

Чтобы записаться, напишите удобный день, время и услугу. Оператор свяжется с вами и подтвердит запись. Бот сам не оформляет запись автоматически.

#### «Подготовка»

Перед визитом или консультацией подготовьте краткое описание задачи, важные детали и, если есть, фото или документы. Так специалист быстрее подберёт решение.

#### «Адрес/контакты»

Mira Studio работает по предварительной записи. Точный адрес и контакты специалист отправит после подтверждения обращения.

### Распознавание текстовых вопросов

Бот должен искать ключевые слова без учёта регистра.

Минимальные группы ключевых слов:

- стоимость: `цена`, `стоимость`, `сколько`, `прайс`;
- запись: `запись`, `записаться`, `записать`, `приём`, `прием`;
- адрес и контакты: `адрес`, `где`, `контакты`, `находитесь`;
- подготовка: `подготовка`, `подготовиться`, `что взять`;
- услуги: `услуги`, `делаете`, `помогаете`.

Если найдено совпадение, бот отправляет соответствующий FAQ-ответ.

### Fallback

Если текст не содержит известных ключевых слов, бот должен отправить сообщение:

> Я пока не нашёл точный ответ. Выберите раздел в FAQ или нажмите «Связаться с оператором», чтобы оставить сообщение специалисту.

Fallback не должен создавать запись в SQLite.

### Связь с оператором

- Нажатие кнопки «Связаться с оператором» переводит пользователя в режим ожидания следующего сообщения.
- Следующее текстовое сообщение пользователя считается обращением.
- После сохранения обращения состояние ожидания должно завершаться.
- Если пользователь после этого пишет обычный вопрос, он снова должен обрабатываться как FAQ или fallback.

### SQLite

- При запуске бот должен создать директорию для базы, если она отсутствует.
- При запуске бот должен создать таблицу обращений, если она отсутствует.
- Каждое обращение должно сохраняться отдельной строкой.

### Уведомление владельца

- Если `OWNER_CHAT_ID` задан и является корректным числом, бот должен отправить владельцу уведомление о новом обращении.
- Если `OWNER_CHAT_ID` не задан или некорректен, бот должен сохранить обращение и подтвердить его пользователю, но не должен падать.
- В уведомлении владельцу должны быть:
  - Telegram user id клиента;
  - username при наличии;
  - текст обращения;
  - дата и время создания.

## Нефункциональные требования

### Безопасность секретов

- `BOT_TOKEN` не должен храниться в коде.
- `.env` должен быть добавлен в `.gitignore`.
- В `.env.example` должны быть только шаблонные значения.
- Логи не должны выводить токен бота.
- Итоговые материалы не должны содержать реальный токен.

### Надёжность

- Бот не должен падать на неизвестном текстовом сообщении.
- Бот не должен падать, если `OWNER_CHAT_ID` не задан.
- Бот должен корректно создавать SQLite-базу при первом запуске.
- После перезапуска существующая база не должна очищаться.

### Простота запуска

- Бот запускается локально одной командой Python.
- Зависимости устанавливаются из `requirements.txt`.
- Основная команда запуска должна быть задокументирована.

### Ограничение по стеку

- Python 3.13.x.
- `aiogram==3.28.2`.
- `python-dotenv==1.2.2`.
- Стандартные модули Python:
  - `sqlite3`;
  - `logging`;
  - `datetime`;
  - `os` или `pathlib`.

## Данные и сущности

### Переменные окружения

```env
BOT_TOKEN=put_your_bot_token_here
OWNER_CHAT_ID=123456789
DB_PATH=data/bot.sqlite3
```

### Таблица обращений

Рекомендуемое имя таблицы: `operator_requests`.

```sql
CREATE TABLE IF NOT EXISTS operator_requests (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    telegram_user_id INTEGER NOT NULL,
    username TEXT,
    message_text TEXT NOT NULL,
    created_at TEXT NOT NULL
);
```

### Поля обращения

- `id` — внутренний идентификатор обращения.
- `telegram_user_id` — Telegram id пользователя.
- `username` — username пользователя при наличии.
- `message_text` — текст обращения.
- `created_at` — дата и время создания обращения в ISO-формате.

## Архитектура и поток данных

### Запуск

1. Python запускает `service_studio_bot/main.py`.
2. Код загружает `.env`.
3. Код проверяет наличие `BOT_TOKEN`.
4. Код создаёт директорию для SQLite-базы.
5. Код создаёт таблицу обращений, если она отсутствует.
6. Aiogram запускает long polling.

### FAQ-поток

```text
Пользователь
  -> /start или FAQ-кнопка
  -> aiogram handler
  -> FAQ answer
  -> ответ пользователю
```

### Текстовый поток

```text
Пользователь
  -> текстовое сообщение
  -> проверка состояния ожидания обращения
  -> если состояние активно: сохранить обращение
  -> если состояние не активно: поиск FAQ по ключевым словам
  -> если совпадение найдено: FAQ-ответ
  -> если совпадение не найдено: fallback
```

### Поток обращения к оператору

```text
Пользователь
  -> нажимает «Связаться с оператором»
  -> бот включает режим ожидания сообщения
  -> пользователь отправляет текст
  -> SQLite insert
  -> подтверждение пользователю
  -> уведомление OWNER_CHAT_ID, если возможно
  -> завершение состояния
```

## Ограничения и допущения

- Бот работает только через Telegram long polling.
- Бот запускается локально, без сервера и webhook.
- Используется настоящий Telegram Bot API через `aiogram`.
- Секреты хранятся только в локальном `.env`.
- В MVP обращение — это одно следующее текстовое сообщение после кнопки «Связаться с оператором».
- Бот не обещает автоматическую запись, оплату или моментальный ответ специалиста.
- Если пользователь отправляет не текст в режиме обращения, допустимо попросить отправить текстовое сообщение.
- Хранение персональных данных ограничивается Telegram id, username, текстом обращения и датой создания.

### Проверка Telegram-сценариев

Перед завершением нужно вручную проверить в Telegram:

1. Запустить бота локально.
2. Отправить `/start`.
3. Убедиться, что пришло приветствие и FAQ-меню.
4. Нажать минимум две FAQ-кнопки.
5. Отправить `Какая стоимость?`.
6. Отправить `Как записаться?`.
7. Отправить `Где вы находитесь?`.
8. Отправить `У меня другой вопрос`.
9. Нажать «Связаться с оператором».
10. Отправить короткое обращение.
11. Проверить подтверждение пользователю.
12. Проверить уведомление владельцу при корректном `OWNER_CHAT_ID`.
13. Проверить строку в SQLite.
14. Перезапустить бота и убедиться, что база не очищается.

### Проверка SQLite

После тестового обращения нужно убедиться, что в базе есть строка с полями:

- `id`;
- `telegram_user_id`;
- `username`;
- `message_text`;
- `created_at`.

### Проверка секретов

- Реальный `BOT_TOKEN` отсутствует в коде.
- Реальный `BOT_TOKEN` отсутствует в `spec.md`.
- Реальный `BOT_TOKEN` отсутствует в логах и итоговом отчёте.
- `.env` не должен попадать в git.
