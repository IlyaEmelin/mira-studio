# План реализации Mira Studio FAQ Bot

План основан на текущей спецификации `spec.md` и выбранном варианте реализации: простой MVP в одном файле `service_studio_bot/main.py`.

## Цель плана

Последовательно собрать локального Telegram FAQ-бота для Mira Studio, который:

- отвечает на `/start`;
- показывает inline FAQ-меню;
- отвечает на FAQ-кнопки;
- распознаёт текстовые вопросы по ключевым словам;
- даёт fallback для неизвестных вопросов;
- принимает одно обращение после кнопки «Связаться с оператором»;
- сохраняет обращение в SQLite;
- уведомляет владельца через `OWNER_CHAT_ID`;
- не хранит секреты в коде.

## Этап 1. Подготовить проектные файлы

### Шаг 1.1. Исправить `requirements.txt`

Сделать файл обычным текстовым UTF-8 без BOM со следующим содержимым:

```text
python-dotenv==1.2.2
aiogram==3.28.2
```

### Шаг 1.2. Обновить `.env.example`

Оставить только переменные, согласованные в спецификации:

```env
BOT_TOKEN=put_your_bot_token_here
OWNER_CHAT_ID=123456789
DB_PATH=data/bot.sqlite3
```

Важно: не использовать `ADMIN_CHAT_ID`.

### Шаг 1.3. Обновить `.gitignore`

Убедиться, что игнорируются:

```gitignore

.env
.idea/

```

### Шаг 1.4. Создать структуру проекта

Создать:

```text

  main.py
data/
  .gitkeep
```

## Этап 2. Настроить конфигурацию и запуск

### Шаг 2.1. Подключить зависимости в `main.py`

Подключить необходимые модули:

- `asyncio`;
- `logging`;
- `os` или `pathlib`;
- `sqlite3`;
- `datetime`;
- `dotenv.load_dotenv`;
- компоненты `aiogram` для `Bot`, `Dispatcher`, обработчиков, фильтров, inline-клавиатуры и FSM.

### Шаг 2.2. Загрузить `.env`

В начале запуска вызвать `load_dotenv()`.

Прочитать:

- `BOT_TOKEN`;
- `OWNER_CHAT_ID`;
- `DB_PATH`.

### Шаг 2.3. Проверить обязательный `BOT_TOKEN`

Если `BOT_TOKEN` не задан, бот должен завершаться с понятной ошибкой в логах.

Токен нельзя выводить в лог.

### Шаг 2.4. Обработать `OWNER_CHAT_ID`

Если `OWNER_CHAT_ID` задан и является числом, использовать его для уведомлений.

Если не задан или некорректен:

- не падать;
- логировать предупреждение без секретов;
- сохранять обращения в SQLite;
- не отправлять уведомление владельцу.

### Шаг 2.5. Настроить logging

Включить базовый logging уровня `INFO`.

Логи должны помогать понять:

- что бот стартовал;
- что база инициализирована;
- что обращение сохранено;
- если уведомление владельцу не отправлено.

Логи не должны содержать `BOT_TOKEN`.

## Этап 4. Реализовать SQLite

### Шаг 4.1. Создать директорию для базы

Перед подключением к SQLite убедиться, что директория из `DB_PATH` существует.

Например, для `data/bot.sqlite3` должна существовать папка `data/`.

### Шаг 4.2. Создать таблицу `operator_requests`

Использовать схему из спецификации:

```sql
CREATE TABLE IF NOT EXISTS operator_requests (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    telegram_user_id INTEGER NOT NULL,
    username TEXT,
    message_text TEXT NOT NULL,
    created_at TEXT NOT NULL
);
```

### Шаг 4.3. Реализовать функцию сохранения обращения

Функция должна принимать:

- `telegram_user_id`;
- `username`;
- `message_text`;
- `created_at`.

Функция должна выполнять `INSERT` и сохранять изменения через `commit()`.

### Шаг 4.4. Проверить SQLite локально

После реализации выполнить короткую проверку создания базы и таблицы без Telegram-сценария, если возможно.

## Этап 7. Реализовать текстовые FAQ-вопросы и fallback

### Шаг 7.1. Создать функцию поиска FAQ по тексту

Функция должна:

1. принимать строку пользователя;
2. приводить её к нижнему регистру;
3. искать ключевые слова;
4. возвращать подходящий FAQ-ответ или `None`.

### Шаг 7.2. Добавить обработчик обычного текста

Если пользователь не находится в режиме обращения к оператору:

- при совпадении ключевых слов отправить FAQ-ответ;
- при отсутствии совпадения отправить fallback и FAQ-меню.

### Шаг 7.3. Проверить текстовые вопросы

В Telegram отправить:

```text

Как записаться?
Где вы находитесь?
Как подготовиться?
У меня другой вопрос
```

Ожидаемый результат:

- первые четыре сообщения получают FAQ-ответы;
- неизвестный текст получает fallback;
- fallback не создаёт строку в SQLite.

## Этап 8. Реализовать обращение к оператору

### Шаг 8.1. Добавить состояние ожидания обращения

Использовать FSM aiogram или простой in-memory флаг состояния пользователя.

Предпочтительно использовать FSM aiogram, так как это штатный механизм для aiogram 3.

### Шаг 8.2. Добавить обработчик кнопки «Связаться с оператором»

При нажатии:

1. перевести пользователя в состояние ожидания сообщения;
2. отправить инструкцию: пользователь должен написать короткое сообщение для специалиста.

### Шаг 8.3. Обработать следующее текстовое сообщение

Если пользователь находится в состоянии ожидания обращения:

1. взять текст сообщения;
2. сохранить обращение в SQLite;
3. подтвердить пользователю приём обращения;
4. отправить уведомление владельцу, если `OWNER_CHAT_ID` корректен;
5. завершить состояние.

### Шаг 8.4. Обработать не текст в режиме обращения

Если пользователь отправил не текстовое сообщение, бот должен попросить отправить текст.

SQLite-запись в этом случае создавать не нужно.

### Шаг 8.5. Проверить завершение состояния

После сохранения обращения отправить обычный FAQ-вопрос, например:

```text
Какая стоимость?
```

Ожидаемый результат: бот отвечает как FAQ, а не сохраняет второе обращение автоматически.

## Ошибки и решения

### Ошибка 1. `ModuleNotFoundError: No module named 'aiogram'`

Контекст: быстрая проверка импорта была запущена параллельно с установкой зависимостей.

Статус: решено.

Решение: после завершения `python -m pip install -r requirements.txt` импорт `aiogram` и `dotenv` успешно проверен повторно.

### Ошибка 2. `PermissionError` при удалении временной SQLite-базы на Windows

Контекст: проверка SQLite и keyword matching успешно вывела `sqlite_and_matching_ok`, но затем упала на удалении временного файла SQLite из-за Windows file lock.
